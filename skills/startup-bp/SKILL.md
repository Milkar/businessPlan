# 创业项目 BP 生成与迭代

这个 skill 把一个创业项目的零散材料（原 BP PPT、科学家的技术文档、团队简历、融资信息）
变成一份**投资人能在 3 分钟内抓住要点、在尽调时经得起追问**的商业计划书。

读者是投资人：他们一天看几十份 BP，先看摘要和封面决定要不要往下读，
再在尽调时逐条核对数字和说法。所以 BP 要同时满足两件事：
**讲得清（结构、反复强化的核心优势）** 和 **经得起查（数字有出处、不夸大、缺口明示）**。

项目专属信息（AIVC 的封面、融资口径、待决事项）见 `references/aivc-project-context.md`；
每次处理 AIVC 时先读它。

## 工作方式

- **以 Markdown 为工作稿**。PPT / PDF 输入先转成 Markdown 再改（省流量、方便 diff 和版本管理）；
  只有在用户要路演文件时才渲染 PPT（见第 6 步）。
- **版本化**：每轮修改另存为 `<项目>_BP_v<N>.md`，不覆盖上一版；文末附「本次修改说明与待决事项」。
- **建议 ≠ 规则**：你主动提出的结构调整（例如合并章节、换标题）先列为「待确认建议」，
  用户确认后才写进下一版。用户的问题（例如「数据飞轮有没有必要」）先回答，不直接动稿。

## 流程

### 第 1 步：收集材料，建立「事实底稿」

逐份读取材料，记下每一条可用事实及其来源（文件名 + 页 / 节）。
材料之间冲突时（例如执行周期 12 个月 vs 12–18 个月、Level 定义不同），**不要自行择一**：
按下面的优先级处理并标【待核】：

1. 科学内容（机制、验证分级、适应症、技术路线）→ 以**科学家文档**为准。
2. 融资信息（金额、周期、资金用途）→ 以**用户最新口径**为准。
3. 其他 → 以最新材料为准，旧说法在修改说明中注明已作废。

### 第 2 步：搭三段式骨架

按 `references/structure-template.md` 的骨架组织全文：

```
封面 → 0. 一页纸摘要（三个问题各一句话 + 技术优势的三种说法）
第一部分 为什么要做：市场需求与现有缺口
第二部分 为什么我们能做成：护城河与技术优势（含团队、竞争、验证路径）
第三部分 做成之后：社会价值、商业价值、盈利模式、融资与里程碑、投资回报
结语：请记住这三句话
附：本次修改说明与待决事项
```

每一部分末尾放一句「小结」，回答这一部分对应的那个问题。

**增长机制放进技术部分**：数据飞轮、闭环这类「为什么越做越强」的机制，是用来解释技术原理的辅助工具，
放在第二部分的技术实现之后（「为什么模型越用越准」），**全文只完整展开一次**。
护城河、团队、商业模式需要时只引用它（如「飞轮如何加深这道壁垒」），不另设飞轮章节。

### 第 3 步：封面——名称、slogan、价值主张

封面按四层排，从上到下：

1. **项目名称**：2 个汉字 + 1 个英文词。名字本身要指向核心机制或使命，不用「AI / 智能 / 科技」这类泛词，
   也不用超出当前证据阶段的词（如「孪生」）。名称是公司 / 项目品牌，与产品名（如 AIVC）分层。
2. **使命 slogan**：一句话（≤ 20 字）讲清「为谁、用什么、做到什么」。
3. **产品 + 价值主张**：产品名 + 一句讲价值 / 结果的话（≤ 20 字），再用一行说明产品是什么。
4. **融资信息**：金额、覆盖周期、日期。

还没有名称时，先出 1 个推荐方案 + 3 个备选（每个都附含义、slogan 和取向），写进 `docs/naming.md`；
另外列出已排除的撞名方向，并提醒正式做商标（第 5 / 10 / 42 / 44 类）、企业名称和域名检索。
名称在团队选定之前标【待定】。结语的最后一句要和封面的名称、slogan、价值主张呼应。

### 第 4 步：核心优势「反复出现，每次换一种说法」

投资人记住的只有被反复强化的那一两点。全文让**技术优势和价值**至少出现在下列位置，
**每处换一种表达形式，不能复制同一段话**：

| 位置 | 形式 |
|---|---|
| 摘要 | 一句话 / 一个公式 / 一个比喻 |
| 第一部分末 | 行业缺口 = 我们的入口 |
| 第二部分 | 机制图、验证示例、壁垒表、复利逻辑 |
| 竞争格局 | 「别人比 X，我们比 Y」的对比结论 |
| 速记卡 | 按角度（数据 / 方法 / 可信度 / 时间…）的对比表 |
| 第三部分 | 技术优势 → 商业价值的转化链 |
| 结语 | 三句话 |

写完后自查：把这些位置的文字并排放，看有没有两处在说同一句话；有就改写其中一处。

### 第 5 步：可信度规则（不可违反）

- **不编造数字**。没有出处的市场规模、收入预测、估值一律写成「待补充」框架：
  列出要补什么、建议口径，并标【待补充】。可以引用的公开参照（如可比公司融资额）注明来源和年份。
- **示意 ≠ 结果**。科学家给的示意性预期（例如「T0→T1 各特征 ↑↓」）必须注明是假设，
  不能写成已达成的成绩。
- **术语克制**。不夸大成熟度：例如「数字孪生」只用于系统已经达到持续更新、患者特异性决策的阶段；
  适应症写「优先候选、先完成可行性筛选」，不写「已选定」。
- **把克制变成优势**：说明为什么需要校准、前瞻验证、阶段闸门——诚实本身就是给投资人看的风控。
- 标记统一：`【待补充】`= 原稿没有、需团队提供；`【待核】`= 需确认或材料间不一致。
  所有标记在文末「需要确认的事」中汇总。

### 第 6 步：投资人视角补强

成稿前对照 `references/investor-checklist.md` 逐项检查。
缺失项不要编内容，而是在相应章节放「待补充」框架，并在修改说明里按优先级列出，
告诉用户「投资人尽调最可能追问的是哪几项」。

需要深挖时可调用这些能力（如已安装 / 可用）：

- 市场规模、可比公司、行业数据 → `deep-research`，或 WebSearch；每个数字带可点开的来源链接。
- 财务模型（收入预测、单位经济、资金消耗）→ `xlsx`；有 pitch-agent 插件时可参考其 `3-statement-model`。
- 叙事逻辑自查 → strategy-frameworks 插件的 `pyramid-principle`（结论先行）。
- 模拟投资人追问 → cofounders 插件的 `cofounderpitch-prep` / `investor-agent`。
- 路演 PPT → `pptx`（或可用的幻灯片 Artifact 类型），每页一个结论标题，正文精简，图表优先。
  **用户提供了 PPT 模板时，一律在模板上改**：解包模板、保留需要的页、只替换 `<a:t>` 文字（脚本 `tools/slides/edit_runs.py`），不改版式、配色、字体和图形；文字放不下时先精简文字，再考虑字号，最后才问用户。

### 预算模拟与 Plan B 准备金（融资章节）

用户要求做预算 / 成本分析时：

1. 用 `xlsx` 建一个**可改假设**的模型（参考 `tools/budget/build_budget.py`）：「假设」表放全部单价，「人员」表放逐月在岗人数，
   「月度预算」逐月公式汇总，「汇总」给出分配与关键指标，「PlanB情景」给出触发条件与现金跑道。蓝色 = 输入，黑色 = 公式。
2. **自下而上**测算 Plan A（人员 × 薪酬、病例数 × 单例成本、设备、算力、合规、运营），不要按比例拍分配。
3. **融资额 − Plan A = Plan B 准备金**，目标 20%–25%，单独存放；Plan A 内部另设小额不可预见费，两者不混用。
4. 至少三个情景：正常推进 / 科学闸门未过（收缩）/ 闸门未过 + 融资受阻（维持期），算出第 12 个月末现金和总跑道。
5. 写清准备金的触发条件、审批程序和禁止用途；触发条件挂钩验证闸门和下一轮融资时间点。
6. 保守口径：融资期内不计收入。单价是估算的必须标【待核】，并说明是估算而非报价。
7. 环境里 LibreOffice 无法重算时，用 `tools/budget/inject_values.py`（Python `formulas` 引擎）写入缓存值，
   并设置打开时全量重算。

### 第 7 步：交付

1. 新版本 Markdown 文件。
2. 文末「本次修改说明与待决事项」：改动摘要（逐条）+ 需要确认的事（编号列表）。
3. 回复中用 3–5 行说明：本版改了什么、哪些是建议待确认、投资人最可能卡住的缺口是什么。

## 常见局部修改的处理

- **改融资周期**（如 24 → 12 个月）：同步改封面、资金用途、里程碑表、验收指标；
  超出周期的里程碑不要删，移到「下一轮融资目标」。资金占比按新周期重新核对并标【待核】。
- **改封面**：只动主标题时，同步检查结语最后一句是否仍与主标题呼应。
- **并入新材料**：先列出新材料带来的新概念，再决定放进哪一部分；同一概念全文只在一处完整展开，
  其他地方用换说法的方式引用（见第 4 步），避免同一段落重复两次。
